# S1a 群路由核验与依赖收敛

产品修改基于 `f9a693e`。构建：`build/s1a/mac-arm64/FormaBot.app`，应用版本仍为 0.1.0；确切提交与编译文件摘要见该构建目录 `build-info.json`。

## 路由事实与最新需求

原代码正确识别 @ 时直接运行目标 Bot，没有先调用主管模型。未识别到 @ 时回退主管；`@编辑？…` 与全角 @ 的反例实际落到主管。已统一标点和全角 @，并避免短名称误匹配带标点的长名称。

用户随后进一步要求全员静默分析、按需参与、结果通知上游。该需求已写入 requirements 和 S1b 设计。**本片没有实现全员判断，也没有删除旧的默认主管回退和主管汇总。旧路由测试只验证本片防止误投递，不作为新群聊模式验收。**

## 修复结果

- 前置依赖绑定具体 job ID，同成员的不同任务不再互相释放后继。
- 分工入队前检查唯一依赖和循环；整批 SQLite 写入事务化，失败不留下部分任务。
- responded、silent、blocked、执行失败和启动失败均使下游逐层 blocked，不再残留 held 后错误完成。
- completed 才释放后继；重复分工返回既有收据；停止继续覆盖队列。

## 用户手测

退出旧 App，打开 s1a 构建；原模型、工作空间与成员应保持。群里输入 `@某成员？请写一段介绍并保存到文件，然后告诉我位置`，应由被指定成员完成，不先交主管。现有支持分工的群里要求先查找不存在素材、找到后才让另一成员写总结，后继应显示受阻，不能一直等待或编造文件。

本片不是全员静默参与模式，也不是整个 S1 完成。下一片先实现 S1b 新群聊模式，然后继续在途指令/角色版本、可信交付及浏览器与审批。正式发行相关授权与真实用户验收尚未完成。
