# E04b 用户复测：群体要求、搜索及私聊边界

## 复现与判断

用户语句“@抖音运用总监 … 大家收到后回复”原先仅进入mentioned()路由，只有被@者入队。现在提供group_message.recipients=all，由被调用模型理解完整要求后选择广播；不是正则匹配“大家”后强行回复。

原工具目录只有read/write/edit/bash/browser和团队工具，没有搜索。DeepSeek官方Responses API已支持服务端web_search：https://api-docs.deepseek.com/guides/responses_api/ 。新增宿主搜索适配复用当前DeepSeek模型和Key，其他服务商暂不展示此工具。返回完成搜索记录、正文及来源注释，保留取消和超时；浏览器仍可用于打开原文和页面操作。

只读核查用户实际报告：列出多个站点和文章名称，但没有原文URL及明确日期；包括“收藏率权重40%+”等具体结论，缺逐条原始证据。判定是证据不足，不在未独立核验情况下宣称每一条事实均为假；未改写用户文档。搜索引擎是正常入口，不能把使用百度/必应/Google本身当错误，也不能把搜索摘要当核验完成。

数据库核查：用户引用的总结保存在Bot私聊；相应群组另有分册产出、交付和多轮确认，证明任务确有群内扩散。修复会话执行边界：group_message/assign_tasks只能操作当前群，私聊不能自行指定另一个群转发或派单。明确授权的跨会话分享尚未设计完整，目前应由用户在目标群发起协作。
