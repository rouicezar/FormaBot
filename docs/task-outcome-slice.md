# 任务终态事实修复

需求：审计 C02/C04 中，全静默不能声称已回复；TaskTimeout 必须保留中断状态与原因，UI可显示重新入队入口。该片只关闭状态映射反例，不关闭全员分析、显式责任约束、执行隔离、持久恢复或用户验收。

设计：SessionOutcome 增加 silent/interrupted。根汇总优先级 failed > interrupted > blocked > responded > completed；silent 作为不贡献公开结果的终态，仅全部静默时根为 silent。完成与静默混合保留完成，缺回执回应与静默混合保留 responded。超时成员持久化 interrupted，下游不释放，根保留超时原因；停止保持现有 stopped 路径。现有 UI 已支持这两个状态，不增加新的 UI 分支或数据库迁移，不修改历史记录。

验证计划：宿主夹具测全静默/混合结果、超时及依赖收敛、停止优先；持久化根和成员状态；新构建UI读取中断/静默记录、重入队只填草稿。真实模型语义不由夹具代替，用户可在新包复测通知和停止。

新发现：排版有一条正式依赖任务和一条群消息唤醒任务。根因routeMention仅查humanQueue/queue，漏查held；在已有排版等待审查时收到@或全员消息，又排入无依赖任务。隔离反例在原实现下两种路由均失败（生成两条排版任务）。

修复设计：群通知复用当前群、当前成员的待执行或held任务，回执返回真实held状态和已有任务ID；通知仍进群历史，不丢消息、不改原任务依赖；前置completed才运行一次，blocked不得运行。仅修这一路径，不扩大到全员注意力系统，不修改用户记录。
