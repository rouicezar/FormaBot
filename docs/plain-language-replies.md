# 面向普通用户的交流修复

需求：用户要求直接解决工程术语造成理解障碍。所有Bot的聊天和进度应让用户看懂做什么、做了什么、必要时如何检查、接下来谁做及是否需要用户行动；详略依事情，不设置硬字数或套话模板。此次用户明确调整优先级，先修交流，前一准入片仍未宣告手测通过。

设计：统一公开交流契约用于每次执行的最终提示与公开工具字段，现有Bot无需重新创建。职责规定的“只输出HTML/报告格式”作用于交付文件；聊天讲结果和入口。用户明确要求技术解释时允许准确术语、代码和完整证据，不全局替换或删词。工程任务字段留给内部工具，不能复制进公开摘要；保留失败事实、重要限制、审核建议，不把受阻包装成完成。

进度：不再直接展示模型流式句子碎片（截图Both）；只用真实工具事件映射普通语言，模型正在生成时显示处理中。最终正文与文件不被截断。聊天裸HTML标签按字面展示，避免净化后只剩斜线；产物预览独立不改。

验证：契约接入各身份且位于角色/历史之后、公开工具使用同一约束；进度不呈现流式内部词、工具动作保真；Markdown保留代码标签且不可执行。打包UI验证后进行隔离真实模型样例，使用临时素材、既有模型配置，不改生产角色/历史。

待验证，完成后构建并交付本片手测。其余工作链版本、终态封口和角色业务规则冲突仍按原计划，不由交流提示替代执行门禁。
