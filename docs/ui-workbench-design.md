# UI-01：三栏工作台视觉与交互

界面采用灰白中性色、紧凑消息流、细线图标与独立绘制的应用标记。构建和人工验收记录独立于能力完成状态。

## 设计目标

左侧支持快速识别成员，中间呈现完整对话，右侧展示工作内容。长消息、任务进展和产物应易于扫描，右侧空状态提供明确引导。

界面采用灰白中性色、紧凑消息流、细线图标与独立绘制的应用标记。构建和人工验收记录独立于能力完成状态。

## 本轮范围

- 左：清晰成员/群分类、可用的名称/职责搜索、可识别选择态、真实空间路径；保留创建和职责/群设置。
- 中：标题和职责层次、易读的用户/成员消息、长回复可展开、产物明显可点；技术事件默认折叠但错误可见。折叠旧消息不等于实现 R20 服务端防刷屏。
- 输入区：更紧凑的写作区域与明确发送/停止，保留 @、成员选择和真实队列反馈。
- 右：明确浏览器/产物模式、地址与导航、HTML 预览/源码/复制、自然空状态；原生浏览器尺寸跟随、不能覆盖工具栏或弹窗。
- 配置/新建窗口：统一视觉和标签；不改变凭据、授权、后台任务或数据结构。
- 两栏可拖/可收放、键盘焦点与低动态设置保留；桌面最小受支持窗口与宽屏均检查无按钮遮挡。

不增加语音、市场、定时、虚拟电脑、MCP 管理等占位功能；不加载外部字体/图片；不使用截图中的业务数据生成假工作结果。

## 验证与交付

类型检查、现有测试与构建；现有 workbench/right-panel 实机回归，新 UI 用构造内容检查搜索、长文展开、空/错误/任务状态、宽窄布局和截图。界面 fixture 明确不是模型任务；真实模型任务用现有隔离脚本回归，不读取生产私聊。

UI-01 的独立构建保存在 `build/ui-01/mac-arm64/FormaBot.app`，与原 `build/mac-arm64/FormaBot.app` 分开。模型/空间/授权继续复用相同产品 userData；用户不要同时运行两个版本。交付记录提交号与构建路径，并列具体手测项。

手测：确认整体方向、成员搜索/选择/新建、长文展开和产物入口、左右收放拖动、HTML 源码复制、浏览器地址导航、设置返回与重启配置保留；随后提交一个小的真实工作任务，确认执行/停止与反馈可见。权限反例仍由开发测试承担，不让用户试险。

用户确认通过后合并 UI 分支到 main；有反馈先修本片并重新构建，未通过不合并、不进入下一 UI 阶段。当前尚未手测或合并。

### UI-01c 身份图标

群组与 Bot 使用不同图标系列；同类包含多种图案，按创建时分配颜色与图案并保存在本机界面配置中，以持久 ID 关联。名称/职责修改、搜索、排序、切换与重启不改变视觉身份。列表、会话标题和成员消息共用映射。颜色之外保留不同图形与真实名称。有限色板循环复用，但不让整组成员使用同一图标/颜色。

### UI-01d 小轮廓头像

用户拒绝线框图标加底色方块，改用直接着色的小型角色轮廓与白色眼睛，不加外层背景。列表24px、标题18px、消息16px；群组/成员分别使用5/7种轮廓，保持已保存颜色/图案序号。消息出现成员时同步出现相同身份头像。

### UI-01e 统一群聊工作台

用户确认第二张参考图为右栏收起状态；左右边栏及拖动/保存完整保留。本片去重复全局顶栏，统一单行会话标题、彩色姓名、小头像、浅灰气泡、紧凑自动增高输入框。正文只把已识别且唯一的 @成员转为可点击身份标签，不将普通文本或同名身份猜为成员；点击打开其私聊并保留当前草稿。连续同成员且同任务的邻近消息压缩重复姓名，不删除内容。群标题用实际成员头像组合，可进入群设置。滚动阅读历史时保留位置，提供回到最新入口。本片不实现未读和列表消息摘要，不把显示整理当执行层防刷屏；逐阶段手测通过前不合并。

### UI-01f 应用图标

界面采用灰白中性色、紧凑消息流、细线图标与独立绘制的应用标记。构建和人工验收记录独立于能力完成状态。

图标方向修订：用户明确要求把F的三个组成模块各自做成Bot轮廓，三个Bot对接组成F。每个模块保留一对小眼睛；没有额外肢体/装饰，缩小后仍以整体F识别。应用图标的立体质感与聊天中无底色小头像用途不同，不给聊天头像加应用图标底板。
