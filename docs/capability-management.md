## 职责与用户体验

- MCP：接入本地或远程服务的工具。首期支持范围须根据固定 SDK 接口核验后确定，不承诺任意服务器可接入。
- 插件：可版本化的能力包，可包含工具、MCP 配置、Skill 和必要本地运行组件。
- Skill：按需读取的工作方法，不是授权来源；所引用的工具、脚本和子进程仍受执行检查。

核心能力与运行依赖随安装包提供。普通用户在 App 内查看可用能力、连接外部账号、启用/停用扩展，无需装 Node、驱动或执行终端命令。可选扩展由用户明确安装/启用，Bot 不自行下载执行未知代码。缺少能力时简短说明并保留任务；不得假装已安装或静默改用其他服务。

外部服务凭据在 App 中配置并加密保存；只向需要该凭据的适配器提供最小范围凭据，不将完整密钥库、模型 Key 或私人浏览器 profile 注入扩展。平台登录/连接过期可重新连接，不能借此重申请工作空间授权。

## 统一执行流程

1. 宿主能力目录保存稳定 ID、来源、版本、描述、参数 schema、执行类型、本地/远程位置、所需权限与账号、可用状态、依赖和结果格式。模型看到的工具使用唯一命名空间，不能覆盖内置工具。按成员职责和任务检索相关描述，再按需加载完整 schema/Skill，避免全量上下文灌入。
2. 模型选择工具或工作方法；Skill 仅在相关时加载，不强制每个任务套流程。Skill 内容及其引用文件/网页为任务材料，不能覆盖用户要求、成员职责或执行授权。
3. 每次调用携带宿主确认的任务/成员身份、角色与指令版本、能力版本、账号范围和取消信号。宿主检查有效性、schema、职责、工作空间及业务动作范围；目录可见或模型传入“已授权”不代表允许执行。
4. 内置工具、MCP 工具和插件适配器走统一调度与结果通道。本地 MCP 服务/插件脚本须在 E02 可监督环境中执行，网络/账号副作用受 E03 约束；远程 MCP 依赖服务端可落实的权限范围。不能只审查 tool 名称就开放任意服务端动作。不能证明边界的扩展不开放到真实业务。
5. 结果区分正常、失败、超时、取消及需要用户处理；外部返回文本视作不可信资料，不能据此自动安装扩展、改变角色或扩大权限。记录来源/版本、调用 ID、必要诊断及实际产物；产物进入指定目录并可预览。大结果有界处理，完整数据保存为可访问产物或引用。
6. 只将简短工作状态更新到任务卡，结论和产物进入聊天；原始工具日志、凭据和模型思考不进入群消息。读取可有限重试，发布等副作用须有幂等/对账机制，否则明确待核实，不盲重试。

统一入口不能代替 OS 或远端服务的强制边界。MCP 本身不作为沙盒，插件脚本不能绕过文件、网络、进程和账号限制；“有工具能力”与“成员负责这项工作”分别检查。

## 生命周期与持久状态

插件安装、启用、停用、升级、移除均有明确状态，校验来源、包完整性、兼容版本和权限声明。权限扩大需用户明确处理，不沿用旧范围静默启用。运行任务固定能力版本；停用先阻止新调用，取消/排空在途工作，记录结果，不能留下后台副作用。升级失败保留可回滚版本；移除扩展不自动删除用户产物或清空工作空间配置。共享配置、成员可用范围、账号授权与版本重启保持。

本地 MCP 启动/握手/超时/退出/进程回收纳入宿主生命周期；远程连接断开/凭据过期保持任务可解释状态。具体传输协议、依赖供应和第三方兼容清单在实现前核验固定版本接口。文档内不会编造当前不存在的安装或测试命令。
