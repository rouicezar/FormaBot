# 已确认需求 / Requirements baseline

来源：本任务中的用户逐轮澄清。记录需求，不代表功能已实现。项目暂名 FormaBot；当前实测 macOS arm64，正式发行平台与完整可用模型清单待验收。实现结果见 [状态矩阵](status.md)。

| ID | 用户需求 |
| --- | --- |
| R01 | 本地桌面 AI 团队应用，支持持久成员、私聊、群聊与可追踪任务交付。 |
| R02 | 用户自定义持久成员及其职责；成员能够建群、组队、分配工作和交接任务。 |
| R03 | “任命领导”仅指协调和分工，不引入额外职位体系。 |
| R04 | 人类可以私聊任意成员，在群里布置任务或指定成员，执行期间追加指令、调整或停止。 |
| R05 | 预置多种云端模型及服务商；选择模型并填写 API Key 即可配置。各成员可选不同模型。 |
| R06 | 每个成员必须具备读取、写入、编辑文件、Bash 和浏览器操作能力。 |
| R07 | 用户可在 App 指定并保存本地工作空间及空间内产出文件夹（outputs 仅为默认，可改），任务默认在这里执行，文件直接落地，对话中展示可打开的产物。 |
| R08 | 安装后第一次任务的实际执行前，主动请求工作空间授权；未授权不能开始实际操作。 |
| R09 | 同一工作空间仅授权一次并持久保存。所有成员、新成员、建群、委派、后续任务和重启均复用授权。撤销或超出原范围时才另行请求。 |
| R10 | 成员之间的权限和信息边界必须明确。委派不扩大原授权，不用内部权限处理制造重复授权。 |
| R11 | 能使用浏览器登录平台、抓取数据、上传及发布作品；具体平台支持需要实际验证。 |
| R12 | 设计等成员可配置和使用生图模型，生成图片并保存到工作空间指定产出文件夹；不能把图片理解能力当作生图支持。 |
| R13 | 用户可以给主管成员一份业务文档，让其创建持久团队、专业成员和群组，保存职责、输入输出与交接规则；不能只输出建队建议。 |
| R14 | 通用安装包内置 DeepSeek Harness、必要插件、运行时和浏览器组件；用户无需另行下载安装依赖或使用终端，首次启动不下载执行组件。在 App 中配置模型和 API Key、选择工作空间并授权即可运行。视觉后置不等于配置界面后置。 |
| R15 | 所有实际 Agent 任务接真实模型；不以模型替身执行任务或宣称链路通过。纯权限、存储等非模型测试可独立执行；未配置模型时任务保持未执行。 |
| R16 | 模型、加密 Key、工作空间及授权持续保存，跨任务、重启和更新复用；失败不得清空。 |
| R17 | 首次模型与工作空间配置完成后进入独立三栏工作台：左栏管理 Bot/群组，中栏会话与任务过程，右栏内置浏览器与产物预览。浏览器任务自动展开右抽屉，点击产物预览；左右抽屉独立开关，两条分隔线可拖动并记住宽度。 |

## 需要在设计中确定

- 首发操作系统和最低版本；Bash 在各平台的供应方式。
- 预置服务商/模型清单及工具调用、视觉能力要求；不承诺所有模型都有同等执行能力。
- 工作空间授权的身份、持久化、撤销和路径迁移处理。
- 成员私聊、记忆、群消息、任务上下文和账号的共享规则。
- 外部发布的常设授权范围与执行校验；不能每次重复要求工作空间授权。
- 同账号浏览器并行、同文件写入冲突、重试幂等、暂停恢复。
- 专用浏览器、系统沙盒、虚拟机和本机桌面控制的组合。

## 范围解释

用户授权了开发准备，不代表已授权真实平台发帖、读取全部个人文件或导入个人浏览器凭据。
工作空间持久授权是产品行为；当前开发工具仍遵循宿主环境权限。
本地执行不承诺关机后继续运行，也不意味着模型请求不会离开本机。

## 群组与预览的功能补充

R18：群组共享消息、@ 定向响应与全员广播、协调人实际分工、成员接收/执行/回复、可追踪状态与群内交付；人类可以持续发言和停止。仅保存群名和成员列表不算群组能力完成。

2026-09-12 用户澄清：群内 @ 某成员即直接将消息交给该成员理解、执行并回复，不先经过专门委派员。协调人不是所有消息的必经入口；成员仅在用户要求协作或任务确有协作需要时组织后续工作，不能把本人应承担的任务默认转给别人。保留用户明确的全员要求，不把 @ 定向理解成删掉消息其余内容。

同日进一步澄清（优先于旧的默认协调人路由）：群内业务消息对所有成员可靠投递，各 Bot 先静默分析自身是否应回应、参与或执行；需要时才公开回应并接任务，完成后交付产物并通知上游。不得设置固定委派员，也不得由隐藏的总控 Bot 代替全体成员判断。用户 @ 决定直接责任，不剥夺其他成员理解消息的机会；其他成员不抢占该责任。用户直接交办的上游是用户，成员交办的上游是对应成员。静默判断与公开发言/实际副作用必须区分；同一事件对同一成员只处理一次，保留去重、取消、依赖与权限边界。

R19：产物可渲染预览或查看源码，HTML 必须提供两种模式与源码一键复制；内置浏览器须具备地址栏、刷新、前进/后退等常用导航操作。

R20：Bot 私聊与群组采用简洁工作沟通，禁止重复长文刷屏，不输出模型推理/思考内容。状态更新、必要摘要和完整产物分开；分工、回执与汇总不得重复淹没工作页面。

R21：Bot 创建后持久遵守身份职责，私聊、群聊与 @ 均一致；用户或有权上游未明确变更前不自行越岗或改岗。用户或有权上游管理者明确变更后立即使用新身份职责，变更持久保存，来源和生效过程可验证，不扩大工作空间/账号权限。

R20/R21 及相邻行为规则、实施顺序与反例见 [成员行为规范](member-behavior-contract.md)。规范已记录，不代表功能已实现。

R22：连接提示使用当前执行 Bot 实际采用的模型标识，例如 deepseek-v4-flash 已连接；不使用“正在连接真实模型”。仅收到有效模型响应后显示已连接，连接失败不能误报。

R23：文档驱动建队必须有普通用户可用的 App 输入路径（粘贴文本或选择/引用本地文档），读取用户指定内容及版本并创建真实实体、显示在侧栏；不能由开发者预置测试数据库代替用户流程。拖拽等具体交互待设计。

R24：产品通用，不将抖音、X、固定五岗位写死。当前文章测试按用户纠正采用抖音与本地路径；文章五岗和用户明确指定的口播/视频五岗分别保留，当前明确指令优先。五名专业成员不包含已有主管，管理/汇报关系需持久保存。

全部沟通细节与任务/验收的映射见 [覆盖复核](conversation-coverage.md)。

## 统一能力管理

R25：App 提供统一能力目录与插件生命周期管理，核心能力及必要运行组件随包提供；按成员职责/任务发现能力，用户配置持久保存。可选扩展明确安装启用，Bot 不自动下载执行未知插件或静默扩权。

R26：本地/远程 MCP 工具接入宿主统一执行通道，核验任务/成员/角色版本、空间/账号/业务动作范围；凭据最小提供、调用可取消、错误可追踪、产物本地登记。MCP 接入不绕过执行隔离，不重复申请已有空间授权。

R27：Skill 作为按需工作方法加载，所调用工具/脚本受相同执行检查；Skill 和外部返回内容不能改写身份或授予权限。结果遵守摘要、防刷屏和思考排除规则，缺能力或失败不得伪报成功。

详细设计与验收见 [统一能力管理](capability-management.md)。本轮加入计划，不代表已接入通用 MCP/插件/Skill。

## 工作台身份识别补充

群组与 Bot 都要有身份图标；不同群组和不同 Bot 分配不同颜色及多种图案，不能全部使用相同图标和颜色。分配稳定保存，列表、标题和消息一致，不能因重启或切换而变化。

头像外观补充：采用小尺寸彩色角色轮廓，可优化形状；不加背景底色，不做大头像，成员在对话中出现时同步显示头像。

### 最新群聊交互补充（2026-09-09）

R20的简洁为Bot行为指导，不是App字数、行数或固定发言次数限制；Bot依上下文与身份职责判断回复时机、内容与详略。App负责重复展示治理、内部思考隔离、Markdown渲染和长文展开。群聊输入@在文本光标附近显示本群成员，支持中文/字母片段筛选与键盘/鼠标选择。产物为超链接，点击打开**右侧**预览，左侧保留群组/Bot管理。

DeepSeek预置补充 `deepseek-v4-flash-vision-exp`；模型选项与图片实际传入是两项验收，图片附件/识图端到端尚待实施，不以预置ID完成替代。

群聊补充：定向@不覆盖消息中对全体成员的要求，由模型理解完整上下文并调用全员通知能力；避免将群体要求限定为被@者。联网研究具备服务端搜索入口，结果保留原始来源、日期和核验状态；不能仅列站点名便声称交叉验证。私聊交付默认留在原会话，不因成员领导身份自动转发或向群派单。

前端执行反馈：每个实际运行的Bot显示动态头像及当前任务提示，任务结束/停止清除；正式回复渐进展示，思考和工具参数不进入对话。正文横向适配聊天区宽度；左下设置入口，空间信息放设置内；浏览器跳转用图标，操作图标具有中文悬浮提示。用户确认本轮UI后，重点回到后端尽责/守界/适时回应/协同及产物质量。

## 名称唯一性补充

同一工作空间内，Bot之间不能重名，群组之间不能重名；创建和改名均提示“名称已存在”并阻止保存，模型批量建队同样适用。忽略首尾空白、字母大小写和Unicode规范等价写法。按类型分别校验，不跨工作空间限制。历史重复实体不自动合并或删除，需保留ID与聊天记录；对已有重复名称的整理另行处理。

## Bot删除补充

Bot编辑页提供“删除 Bot”，二次确认文案：“一旦删除Bot，该Bot的所有数据将被清空，你确定要删除吗？”默认取消。确认后删除应用内身份/职责、私聊、可归属群发言、任务及运行数据，移出所有群组；其他成员记录、共享账号/配置、已交付的工作空间文件保留，确认框明确范围。执行任务期间禁止删除；取消无副作用，删除最后Bot不自动重建。既有同名副本仅在核实没有聊天/任务后按用户明确授权清理，不按名称盲目批量删除有记录的Bot。

## 侧栏右键菜单

Bot和群组支持右键菜单：置顶/取消置顶、移至侧栏分组、标为未读/已读、编辑资料、创建副本、复制对话ID、从侧栏隐藏和二次确认删除。分组仅组织侧栏，不改职责/群成员；状态重启保存。隐藏会话可在设置恢复。副本获得新ID及不重复名称，仅复制资料配置；群组副本引用已有Bot，不复制聊天、任务和授权。删除群组保留成员Bot及其他会话。菜单采用紧凑细线图标、分隔线和红色删除，支持鼠标和键盘操作。

## R28 自动更新与版本

设置显示真实版本/构建号和检查更新；发现可用版本后显示蓝色圆形下载图标及中文悬浮提示，用户点击下载、安装并重启。任务中不擅自重启，升级保留模型Key、空间、授权、Bot/群组、历史与本地文件。签名、更新源、迁移失败恢复属于正式能力，不允许只做按钮。验收A23，计划E13。

## R29 浏览器区域选择

用户开启选择后对文字/图片/组件吸附选取，半透明蓝色渐变高亮，可调整范围、取消并添加到对话。文字精确取选中片段，图片/组件传裁剪图像；材料卡确认发送后模型仅处理选择范围，不默认处理整页。跨域/特殊元素允许可见拖框降级，明确限制；用户选择时暂停Bot抢控。验收A24，计划E12。

后端R18/R20/R21的进一步设计以[后端架构](backend-architecture.md)为准：模型根据上下文与职责选择行动/回应/静默，宿主保证稳定身份、可靠投递、权限、交接和真实验收，不靠固定话术与关键词限制代替语义理解。

## R30 逐动作审批与规则化自动审查（2026-09-11）

审批规范：工作空间基础授权之外，高风险动作（外发/发布、删除或覆盖数据、更改权限、支付、生产变更、法律条款）在执行前逐动作审批，语义为三档：放行一次、拒绝、始终允许（可保存按动作+目标+内容匹配的规则，窄规则优先）。规则化自动审查在工具调用前评估：要求审批的规则始终拦截并优先于放行规则；自动审查基于模型，只作最小权限的补充，不替代执行层限制。审批展示当前值、建议值和预期影响，无法识别目标或效果时不放行。验收并入 A04/A05，计划 E03b（形态定案依据本条）。

## R31 敏感值掩码与人工接管协议（2026-09-11）

密码、双因素验证码、CAPTCHA、支付确认由用户亲自完成：用户可从 Bot 手中接管共享浏览器，完成敏感步骤后归还；敏感值在对话中掩码显示、不进入对话记录、对模型不可见，普通聊天不得作为凭据通道。安全关键决策必须以文字确认，轻量确认（表情/图标）不构成授权。人类接管期间 Bot 不抢控、同页面动作串行（与 E03a 资源租约同一机制）。验收并入 A09/A10，计划 E03a。

## R32 例行任务运行边界（2026-09-11）

FormaBot 执行在本地，App 不运行时任务不执行；产品承诺必须诚实：定时/触发类例行任务只在 App 运行期间调度，错过的时间点不自动补跑，设置与任务卡中明确标注该边界。后台常驻或开机自启属于未来独立决策，不暗示云端等效。验收并入 A17/A18，计划 E06/E08 相关切片。

## 默认全能 Bot 与身份转变（用户补充 2026-09-11，设计待定）

用户进入产品后只有一个默认 Bot：在用户为其指定新身份之前，它等同于一个通用 agent 工具（查询、搜索、本地文件操作、创建群组/Bot、分配职责与命名、按流程执行任务等）；用户一旦给定新身份，它立即完成角色转变，进入并严格守住新身份边界、履行新职责。它受用户指示创建 Bot 时须为其制定明确职责，必要时向用户澄清后创建正确；也可按用户指示将某职位的 Bot 移出群组。移出群组保留该 Bot 本体与历史发言归属（按 E05a 稳定 ID），其未完成任务需明确归属或终止。默认 Bot 是最高权限入口，其创建/授权动作继承既有执行边界（E02/E03），不因"默认"身份扩大权限。与 E05a/E05b/E06c 的切片归属在下一片设计时确定，未实现前不宣称具备。

### 执行过程行（2026-09-12 用户补充）
私聊及群聊的当前 Bot 消息在名字下方用单行浅色文字显示真实执行步骤，配对应动作图标及轻微扫光，随事件即时更新，完成后收起。不得放在工作区底部、逐步骤新增聊天消息或虚构执行速度。减少动态效果偏好下停用扫光。

### 标题栏群组归属（2026-09-12 手测反馈）
群组头像起点与中间工作区左边界对齐，跟随侧栏宽度变化；侧栏收起时保留原生窗口按钮空间。标题栏运行环收至头像内部，细线低透明度，无外发光及缩放呼吸，不改变其他位置的成员身份。

### 执行叙述与正式回复分流（2026-09-12 手测反馈）
模型运行中未确认最终的流式文字仅进入浅色单行，工具步骤继续在同一行替换；不按中英文或固定句式猜测。最终结果通过现有交付通道进入消息气泡，明确发送的群消息保留。

### 单一发送/停止按钮（2026-09-12 手测反馈）
输入框只保留同一个操作按钮：空闲为发送，运行中为停止，停止完成恢复发送；请求处理期间禁用防止重复操作，停止不清除草稿，Enter 不代替主动点击停止。

### 产物时间轴与原群返工（2026-09-12 用户确认）
当前 Bot 的产物面板展示完整历史交付（含其群内署名交付），按真实记录排序；时间缺失的旧产物明确标注。时间轴和聊天链接调用同一预览入口。用户在私聊反馈质量问题时，Bot 根据原任务记录在原群 @ 原交付者返工，支持向更上游继续追溯、逐级复核，最后由原 Bot 回私聊答复。不得把其他 Bot 拉入私聊或因返工另建群；仅转达解决问题所需的信息，沿用跨会话必要包审批。实现与验证见 docs/artifact-rework-slice.md。

## 2026-09-12 最新用户确认：固定项目与紧凑产物

本轮需求验收总账见 [逐项需求与上线门禁](requirements-review-2026-09-12.md)，覆盖 U01–U14。Bot / 群组在创建时绑定当时默认或另选并授权目录，创建后不能修改；新默认只影响未来创建。基于 Bot 创建新项目复用职责与模型，不复制聊天/项目记忆/产物。群任务用群空间，私聊用 Bot 空间。此决定取代此前“中途可修改空间”的提案。

产物支持正文原位置内嵌蓝色链接与蓝色圆角文件小图标；末尾链接同样紧凑，正文已引用产物不重复列出。设置为独立多标签原生窗口，工具栏图标化并提供提示与可访问名称。全员静默判断尚待实现，不能将既有主管分派冒称符合该需求。

### R25 本机工具与设置入口（2026-09-13）
用户要求本机发现不受工作目录限制；设置新增“工具”，统一显示MCP、Skill、扩展及来源、可用状态，后续支持启停和安装管理。发现、兼容、启用、验证可用分别表达。按独立可手测小片实现，不把目录可见当成Bot能使用。

### 工具启用与连接状态（2026-09-13 手测澄清）
所有启用/连接状态只表示FormaBot自己的记录，不继承其他App的启用状态。来源目录仅用于说明发现位置，同名来源需可辨。已启用项置顶分组。Skill启用只是读取工作方法，不代表其所需MCP服务已连接。Figma等需要账号授权的MCP，用户点击连接后立即进入浏览器授权；授权并真实验证通过后才标为已连接，拒绝/取消/失败不得显示已启用或已连接。MCP正式接入片落实此流程；当前Skill片不伪造连接能力。
