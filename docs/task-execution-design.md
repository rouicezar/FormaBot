# 单成员真实任务与基础配置持久化

> 设计与实现分开：本文保留模块目标；当前实现、已知反例见 [状态矩阵](status.md)。实施顺序统一遵循 [整改计划](../tasks/plan.md)，局部成功不等于全部约束通过。

本次修复目标：用户已配置模型和目录后，可在 App 提交任务；当前禁用按钮不是模型错误。基础配置跨任务、重启、更新保留；调用失败不删除配置。仅用户主动修改/删除时更新配置，目录失效提示具体错误并保留记录。

首次执行通过 App 原生授权窗口一次授予 read/write/edit/bash/browser，SQLite 以规范目录路径及设备/inode 记录授权，后续任务复用。授权与成员无关。配置沿用现有 userData，更新不清空或迁移到新目录。

执行流程：主进程验证配置/授权，启动专属 Node sidecar；sidecar 用 DSH SDK 发真实模型请求。禁用 sdk-minimal 原始 shell/editor，注册 FormaBot 五项工具；每次工具调用通过带随机令牌的回环桥接，由宿主校验当前授权再执行。模型 Key 仅进入该请求运行时，不存明文文件或日志；Bash/文件执行子进程使用独立的无 Key 环境。

文件和 Bash 在 macOS Seatbelt 内执行，系统必要资源可读，用户数据限制在授权工作空间。E02a 起任务启动前对工作空间做有上限的硬链接检查并打断 `nlink>1` 文件（复制替换，路径/内容不变；超上限拒绝启动）；每次工具子进程退出后无条件回收同组后台残余。E02b-1 起沙箱出站网络默认拒绝、仅放行 localhost（`network-bind`/`network-inbound` 限本地地址，`0.0.0.0` 监听被拒）；逃逸后代继承沙箱，影响被限定为延迟的工作空间写入。E01/E02/E09/E10 反例已在 audit-design 中转为断言通过。**仍不支持的执行能力**：`setsid`/`detached` 自建进程组的后代仍可逃逸进程组回收（audit E03 保留记录）——完整停止收敛需要 OS 级容器/受控执行环境；评估结论：macOS 公开 API 无 cgroups/pdeathsig 等效机制，Seatbelt 沙箱可继承但不能阻止 setsid，每任务容器或专用用户属发行级改造（E10 前评审），当前以影响收敛为诚实边界，不冒称完整停止。沙箱内出站网络限制属 E03b 的基础；按 R30/E03b 将来以逐动作审批放开特定目标（bash 内 pip/npm 等需外网命令当前失败，属预期行为）。执行层仅 macOS。文件命令通过包内 Node worker 接收 JSON，不拼接 shell 命令。浏览器采用独立 Electron session，外站禁 Node/IPC，仅提供明确的导航、读页面、点击、填表能力；真实外部发布测试不在本次授权内。

任务状态在 SQLite 持久保存 running/completed/failed/stopped/interrupted；重启不自动重放中断任务。UI 展示工具事件、最终文本和本地交付路径。停止后回收已跟踪进程组及工具级同组后台残余；detached 后代逃逸与完整资源账本见整改 E02b。成员/群组已接串行执行边界，完整停止见整改 E02。

验证包括配置与授权跨实例恢复、失败不清空、实际文件/Bash越界实验、打包后接口及真实模型文件任务。无模型替身任务。测试站点浏览器与生产平台能力分别记录。
