# 产物历史与原群返工切片

需求：Bot 产物历史按时间展示、两处入口同一预览；用户在私聊提出质量反馈后，成员在原协作群通知原交付者返工、复核并回报，其他成员不得出现在私聊。

设计：历史从完整消息与交付账本读取，不依赖最近 100 条聊天；保留 task/path 版本标识、真实时间，旧数据缺时间明确标注。当前 Bot 包含其私聊产物及其在群中的署名交付；群视图限本群。切换会话清空旧预览并取消迟到加载。

执行：保留实际执行会话 ID，不能以当前选中会话覆盖。review_context 只返回当前成员曾参与的群任务及其同轮成员任务，不读取其他私聊；request_rework 使用确切原任务编号定位原群和原交付者，只分享问题及验收要求。私聊转群沿用必要包审批，不能以成员名猜测原群。缺原始记录时要求澄清，不创建群或邀请成员进入私聊。返工队列结束后由请求者在群里复核，再由同一请求者回到自己的私聊回报。失败也必须复核说明，不能标为已修复。新返工继续使用原任务编号保留追溯。

验证：完整历史超过 100 条、工作空间及成员隔离、时间排序、会话切换与双入口；原群路由及精确来源、跨私聊拒绝、无私聊历史注入、嵌套返工/失败回报。构建后等待用户手测，真实模型验收与构造测试分开记录。

## 已实现

- 完整消息历史与交付账本构建时间轴；当前 Bot 的私聊产物及群内署名交付均可找到，不截断为最近 100 条消息。时间轴和聊天都用 taskId/path 预览，切换会话取消旧请求并清空旧内容。
- 修复执行会话 ID 被私聊选中状态覆盖的问题；原群也能查看正在执行的任务并停止整轮。
- 原任务查询不读取其他私聊，返工用确切原任务编号约束原群与原交付者。未找到可核验关联时不猜测、不创建群。通用跨成员委派也拒绝以 Bot 私聊为目标。
- 返工成功入队后，执行层结束请求者的当前回合，避免其轮询等待阻塞上游。上游处理后按栈返回复核；跨群先回报原请求群，再继续下游复核，最后只由原 Bot 回私聊答复。
- 已排队的复核不因上游 @ 回报重复唤醒；失败仍返回请求者解释，不能冒称修复。
- 私聊图片不自动带到返工群；跨会话仅分享审批过的问题包，可沿用已有授权。
- 写入快照的编号与预览所用成员任务编号一致；快照和账本摘要来自同一份文件字节。提交结果可声明通过 Bash 生成的产物，验证路径后登记与快照，不再只能收录 write/edit。登记失败不静默吞掉。

## 已验证与边界

- 25 个测试文件、90 项自动测试通过。新增用例覆盖超过 100 条历史、其他作者/工作空间隔离、原群三级返工、跨两个群的回报顺序、失败复核、拒绝私聊目标。
- 打包 UI 回归覆盖时间轴与聊天双入口、跨 Bot 切换清空、800/1440 宽布局，并保留前几轮单行进度、单一发送/停止按钮及标题栏回归。
- 真实模型采用已保存 DeepSeek 配置，在独立目录和工作空间运行。原交付是明确标记的历史测试素材，返工与复核为真实模型；没有使用生产聊天或对外发布。
- `.tmp/live-rework-zBpvQn` 初次完整场景通过；`.tmp/live-rework-6niSXX` 复测暴露请求者轮询阻塞上游，已停止该测试并以执行层让出修复；`.tmp/live-rework-JWEGFc` 断言误限为 read 工具，日志确认主管实际用 Bash cat/grep 检查文件，不能把该脚本失败当产品未读取；`.tmp/live-rework-sN8e6c` 修正验证后通过。
- 旧产物没有时间戳时明确显示“时间未记录”；历史未登记产物、缺少原任务或原交付快照的记录不能凭空重建。原任务查询每群返回最近 60 项候选；更早来源不能据此冒称不存在。
- 返工恢复栈目前是本轮内存状态；中断/重启不会自动恢复整条复核链，仍属于后续任务控制与恢复工作。整轮状态仍沿用现有 responded/completed 聚合，不以转达本身冒称任务完成。
- 本片不等于全员静默判断群聊机制已完成，也不等于可信交付、浏览器审批或发行门槛全部关闭。

## 用户手测

打开本阶段构建，保留已有模型与工作空间。进入有历史交付的 Bot，展开右侧“产物”，从时间轴与聊天分别打开文件，切换另一 Bot 检查没有残留预览。对有可追溯原群任务的 Bot 私聊反馈一个具体缺陷并要求上游返工：必要信息确认后，在原群查看原交付者修改及逐级复核，回到私聊应只看到原 Bot 的回报。旧数据若缺少来源应说明不能确定，不能创建新群或召唤成员进入私聊。
