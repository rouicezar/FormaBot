# FormaBot UI 优化方案(2026-09-12)

范围:仅 `src/desktop/`(index.html 内联样式、renderer.ts、icons.ts、layout.ts)。
原则:不改动 IPC/状态层契约;每个阶段独立构建交付用户手测;视觉打磨优先细节而非重排框架。

## 现状诊断

### A. 设置入口与结构(用户点名问题)
- 侧栏底部"设置"按钮点击后弹出 580px 大 modal,把「模型 / 隐藏会话 / 审批规则 / 工作空间」四块全部纵向堆叠,信息密度低、无分类导航,与轻量点击预期不符(renderer.ts:196, index.html:47)。
- 同一容器复用"欢迎页"(未配置时)与"设置弹窗"两种语义,靠 hidden/class 切换,后续加分类会更难。
- 参照:Linear / Slack / Raycast 的做法——入口是菜单或分类导航,单个分类内容短小、可即时关闭。

### B. 任务执行展示(用户点名问题)
- 群任务:`<details>` + 纯 `<p>` 文本行(`#group-jobs`),无状态徽标、无头像、无操作按钮层级。
- 执行详情:`<pre id="events">` 等宽纯文本,事件不分类型、无图标、无时间戳。
- 对话流中的活跃任务只是一条灰泡文字"正在执行:…",没有独立任务卡片。
- `#task-status` / `#model-connection` 是两行裸文本浮在输入框上方,层级弱。
- 执行过程使用状态提示、可展开步骤与类型图标。

### C. 图标(用户点名问题)
- `settings` 齿轮 path 是自造七边形轮廓,不是标准齿轮(icons.ts:22),观感粗糙。
- 大量文本字符充当图标:`‹`/`›`(侧栏收起)、`＋ Bot`/`＋ 群组`(index.html:41)、`←→↻✕`(浏览器导航,index.html:45),与 SVG 图标混用,粗细不统一。
- `send` 是向上箭头与"发送并执行"语义尚可,但与 `back/forward` 的箭头风格不一致。
- 尺寸散乱:15/16/17/18/20px 各处硬编码,无阶梯。
- 缺常用图标:gear(标准)、chevron-down、check、clock、terminal、globe、file-plus、spinner。

### D. 其他细节(顺手整改)
- 颜色全部硬编码灰值(#f7f7f7/#ededed/#e7e7e7/#ececec…至少 10 种近似灰),无 token;未读点 #287bc1 是全局唯一彩色,与黑白灰体系冲突。
- 字号 9/10/11/12/13px 混用无 type scale;间距 padding 值 5/6/7/8/9/10/11… 无 rhythm。
- accent 为纯黑 #252525,无品牌色;dark 模式缺失(color-scheme:light 写死)。
- composer 主按钮无 loading 态(执行中 run 变灰但不旋转)。
- 对话头 `#conversation-avatar` 里硬编码文本"助"且宽度 22px/height 26px 比例失衡。

## 整改方案(4 个阶段,每阶段可独立手测)

### Phase 1 — 设计 token + 图标库重绘(纯视觉,零逻辑)
1. `:root` 建立变量:灰阶 6 级(--bg/--surface/--border/--ink/--muted/--faint)、品牌 accent(建议低饱和青绿或保留黑但统一)、间距 4/8/12/16、字号 10/12/13/15 四档、圆角 6/8/12。
2. 重绘 `settings` 为标准齿轮(12 齿 cog + 中心圆);补 chevron-down/check/clock/terminal/globe/spinner。
3. 替换全部文本符号图标:`‹›`→icon('left'/'right'),`＋`→icon('plus'),浏览器导航→icon('back'/'forward'/'refresh'/'close')。
4. 统一图标尺寸阶梯:16(行内)/18(按钮)/20(头像内)。
验收:设置按钮、浏览器栏、新建按钮图标精致统一;功能无变化。

### Phase 2 — 设置改为弹出菜单 + 分类标签(用户点名)
1. 侧栏底部"设置"点击弹出 popover 菜单(复用 #conversation-menu 的样式语言):分类项——模型配置、工作空间、安全与审批、会话管理、关于(含运行组件版本)。Escape/外点关闭。
2. 每个分类打开为小尺寸(420px)modal 或右侧滑出面板,只含该分类内容;`#settings` 大卡片退役。
3. 未配置(欢迎态)保留全屏流程,但仅展示「模型 → 工作空间」两步,步骤指示器。
4. 首次执行前的工作空间授权提示不动(遵循 AGENTS.md 授权约束)。
验收:点设置出现菜单而非大弹窗;分类切换无内容丢失;欢迎态流程不变。

### Phase 3 — 执行状态组件重构(用户点名)
1. **活跃任务卡**(对话流内):头像(旋转环)+ 任务标题截断 + 当前步骤(最新 event)+ 耗时计时 + 「停止」;可展开查看时间线。
2. **事件时间线**:events 按前缀分类加图标与颜色(命令=terminal、文件=file、浏览器=globe、模型=spark、审批=shield),相对时间戳,失败红色;默认收起,新事件时显示"最新一条"预览。
3. **群任务列表**:`#group-jobs` 改为成员行卡片——头像、姓名、状态 badge(排队=灰/执行中=蓝绿/完成=绿/受阻失败=红)、指令一行截断、行尾操作(重新入队/停止)。
4. `#task-status`/`#model-connection` 合并为输入框上方一条状态胶囊(连接点 + 状态文案),空时隐藏。
验收:执行中能一眼看到"谁在做什么、到哪一步";时间线可展开;停止/重新入队可用。

### Phase 4 — 整体打磨
1. 未读点、accent、状态色收敛为 4 个语义色 token。
2. composer:run 按钮执行中显示 spinner;hover/active/focus 过渡统一 120ms。
3. 群组/成员头像底色区分(浅色底 + 身份色前景),对话头"助"文字改图标。
4. (可选)dark 模式:token 化后成本极低,单独小阶段交付。
5. 空状态、artifact 卡片、预览面板按钮态按 token 复核一遍。

## 不做的事
- 不引入 UI 框架/组件库(现有零依赖手拼架构,改造成本大于收益)。
- 不改三栏布局结构与 IPC/state 接口。
- 不动授权、审批等产品约束逻辑。
